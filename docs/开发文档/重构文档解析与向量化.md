# RAG模块完善

## 1. 提示词管理支持

提示词是LLM应用中的重要组成部分，系统本身也需要管理和使用提示词。RAG在使用LLM进行文档解析与向量化时，也需要使用提示词。

在`CoreMod`模块下，创建`AIPrompt`实体，用于存储提示词相关信息，包括但不限于：

- Name：提示词名称,最大长度 100,Indexed
- Description：提示词描述,最大长度 500
- Content：提示词内容,最大长度 5000
- GroupName：提示词分组,最大长度 100,Indexed

可根据 Name/GroupName 模糊查询。
唯一索引: Name + GroupName

实体创建后，通过Perigon MCP工具获取编写Dto/Manager/Controller的示例代码，完成后端逻辑和接口的实现。

### 前端实现

在系统配置菜单下，创建提示词管理页面组件，实现提示词的增删改查功能。

## 2.重构文档解析与向量化

微软官方提供了`Microsoft.Extensions.DataIngestion`，以支持对多种文档格式的解析与向量化处理。

现在需要使用它来规范和重构现有的文档解析与向量化模块。

在RAG流程中，也需要使用LLm和embedding模型来辅助文档解析与向量化，所以需要提供模型配置的支持。

首先，查询微软官方文档和github相关文档，了解如何使用`Microsoft.Extensions.DataIngestion`进行文档解析与向量化。

然后，遵照官方推荐的最佳实践，重构现有的文档解析与向量化模块：

1. 使用官方推荐的抽象层接口。
2. 具体的文档解析实现，仍然使用`Kreuzberg`实现，整合到官方的抽象层接口中。
3. 向量化部分，要使用`Microsoft.Extensions.VectorData.Abstractions`提供的接口进行重构。

**模型配置**

`KnowledgeBaseMod`模块下添加新实体`RagAgentConfig`，用于存储RAG流程中使用的模型配置，包括：

- Key：配置项名称，最大长度100，唯一索引
- Value：配置项值，最大长度200
- AIModelInfoId：关联的AI模型实体ID，可为空
- Description：配置项描述，最大长度500
- AIPromptId：关联的提示词实体ID，可为空

模块中添加RagConsts.cs，定义常量：

- SummaryModel = "RagSummaryModel"
- EmbeddingModel = "RagEmbeddingModel"
- GraphModel = "RagGraphModel"
- RecognitionModel = "RagRecognitionModel"
- RerankModel = "RagRerankModel"

以对应配置项的Key，在RAG不同的环节中查询并使用。

### 具体实施步骤

1. 添加缺少的NuGet包引用，要使用最新版本(包括预览版)。
2. 在模块`CoreMod/Services`下，创建`FileProcessors`文件夹，在其中创建相关类，实现文件解析与向量化功能。只包括逻辑实现，不涉及数据库操作，以便在其他模块中复用。
3. `KnowledgeBaseMod`模块中，不应该直接涉及到文件解析与向量化，它只提供业务数据层面的功能，如果有，则需要删除。
4. 重构现有`FileProcessorService`服务，调用新的文件解析与向量化实现。
5. 编写单元测试，确保新的实现功能正确。
   
### 前端实现

在RAG菜单下，添加RAG配置页面组件，只展示定义常量键的配置项(后端提供接口，通过反射获取)，以及查询对应选项的具体配置信息，提供编辑和保存的功能。无法新增和删除配置项。

### 后端RAG调整

要实现完整的RAG功能，除了文本解析和向量化处理外(`CoreMod`),

还要支持向量化查询(`KnowledgeBaseMod`),rerank,LLM总结返回，支持流式，支持**引用来源**。如果目前没有实现这些功能，需要补充实现。
