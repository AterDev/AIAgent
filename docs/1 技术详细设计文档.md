## 基础设施说明

### 业务数据库 - PostgreSQL

**用途**：存储系统业务数据

- **主要存储**：Agent 配置、工作流定义、执行记录、工具定义、用户数据等
- **版本要求**：PostgreSQL 15+
- **特点**：事务支持、ACID 保证、支持 JSON 字段存储配置数据

### 向量数据库 - Qdrant

**用途**：存储和查询文档向量

- **主要存储**：RAG 文档的向量数据
- **版本要求**：Qdrant 1.x+
- **特点**：高性能向量相似度搜索、支持元数据过滤、支持集群部署

### 消息队列 - NATS

**用途**：异步任务处理和事件驱动通信

- **应用场景**：
  - 文档解析和向量化的异步处理
  - 工作流执行事件通知
  - Agent 执行结果回调
  - 系统间的事件驱动通信
- **版本要求**：NATS 2.10+
- **特点**：轻量级、高效、支持发布-订阅和请求-响应模式

### 缓存层 - Redis

**用途**：热数据缓存和会话管理

- **缓存内容**：
  - 模型配置信息
  - Agent 配置
  - 热查询的知识库数据
  - 用户会话状态
- **版本要求**：Redis 7.0+
- **过期策略**：根据数据特性设置合理的 TTL

### 容器编排 - .NET Aspire

**用途**：本地开发环境编排和云端部署

- **本地开发**：AppHost 项目统一管理所有服务依赖
- **服务发现**：自动化服务发现和负载均衡
- **配置管理**：统一的配置文件管理

## 知识库模块

### 模块概述

知识库模块提供文档管理、解析/训练和知识库检索能力，使 Agent 能够基于知识库进行推理。

### 核心功能流程

<details>
<summary>📄 文档上传处理流程</summary>

1. **接收文件**
   - 用户上传文件到系统
   - 验证文件格式、大小、完整性

2. **格式解析/训练**
   - TXT/Markdown：按段落分割
   - PDF：使用 PDF 库提取文本（包含 OCR 支持）
   - Office（DOCX/PPTX/Excel）：提取正文和元素
   - 图片/扫描件：调用 Vision 模型进行 OCR
   - 调用 LLM 时提示词复用 SystemConfig

3. **分块处理**
   - 将长内容分割成 512-1024 token 大小的块
   - 相邻块保持 20% 的重叠以维持上下文连贯性
   - 优先在语义边界（段落、句子）处分割

4. **向量化**
   - 调用 embedding 模型生成向量
   - 存储向量及其元数据

5. **存储索引**
   - 将向量和元数据存储到数据库
   - 为向量表创建 IVFFLAT 索引

</details>

<details>
<summary>🔍 知识库检索流程</summary>

1. **混合检索**
   - **向量检索**：计算查询向量，搜索相似度最高的文档块
   - **关键词检索**：使用全文索引搜索包含关键词的内容
   - **结果融合**：向量结果权重 70%，关键词结果权重 30%

2. **排序和过滤**
   - 按相关性评分排序
   - 应用相似度阈值过滤
   - 返回 Top-K 结果

3. **上下文提取**
   - 保留文档的原始来源信息
   - 提供文档块的位置信息

</details>

### 关键实现点

- **向量模型选择**：使用 `text-embedding-3-small` 或国产替代方案
- **检索算法**：混合检索（向量 + 关键词）提高准确率

  - 异步批量向量化处理
- **多租户隔离**：所有查询必须过滤租户 ID
- **元数据存储**：在 Qdrant 中存储文档 ID、租户 ID、标签等元数据用于过滤

## Agent 模块

### 模块概述

Agent 模块提供 AI Agent 的配置、管理和执行能力，支持使用 OpenAI Function Calling 和 MCP 工具进行智能任务执行。

### 核心架构

<details>
<summary>🤖 Agent 执行流程</summary>

1. **初始化**
   - 加载 Agent 配置（模型、系统提示词、工具列表）
   - 准备执行上下文

2. **消息处理**
   - 接收用户输入消息
   - 构建消息历史

3. **模型推理**
   - 发送消息和工具定义给 LLM
   - LLM 返回响应或工具调用指令

4. **工具调用**
   - 解析模型返回的工具调用
   - 执行工具（通过 MCP 框架）
   - 收集执行结果

5. **结果反馈**
   - 将工具结果反馈给模型
   - 模型继续推理或生成最终响应

6. **完成**
   - 返回最终响应给用户
   - 保存执行记录

</details>

## MCP 工具模块

### 模块概述

MCP（Model Context Protocol）是标准化 AI 应用与外部工具和数据源集成的协议。系统通过 MCP 框架统一管理和执行工具。

### 工具定义和执行

<details>
<summary>🛠️ 工具定义规范</summary>

工具按照 MCP 标准定义，包括以下元素：

**工具基本信息**
- 名称：使用 snake_case 格式
- 描述：清晰说明工具功能
- 版本号

**输入参数**
```json
{
  "type": "object",
  "properties": {
    "param1": {
      "type": "string",
      "description": "参数描述"
    }
  },
  "required": ["param1"],
  "additionalProperties": false
}
```

**输出格式**
- 成功响应结构
- 错误响应结构
- 返回数据字段说明

</details>

<details>
<summary>⚙️ 工具执行管道</summary>

1. **权限检查**
   - 验证应用是否有权限调用该工具
   - 校验应用可用工具清单

2. **参数验证**
   - 验证输入参数是否符合 schema
   - 类型检查和值范围验证

3. **超时控制**
   - 设置执行超时（推荐 30 秒）
   - 超时后安全中止

4. **执行工具**
   - 调用工具实现逻辑
   - 捕获异常和错误

5. **记录审计**
   - 记录工具调用信息
   - 记录执行结果

6. **返回结果**
   - 返回结构化结果或错误

</details>

## 工作流模块

### 模块概述

工作流模块提供定义和执行自动化工作流的能力，支持复杂的多步骤流程编排，并优先复用 MAF 的工作流定义格式。

### 工作流执行

<details>
<summary>📋 工作流定义和执行流程</summary>

**工作流定义**
- 步骤序列
- 步骤间的转移关系
- 条件分支逻辑
- 全局变量定义

**工作流执行**
1. 加载工作流定义
2. 初始化全局变量
3. 按序执行步骤：
   - 解析步骤配置
   - 执行对应操作
   - 收集输出结果
4. 评估转移条件
5. 决定下一步
6. 循环直至完成

**进度通知**
- 通过 WebSocket 实时推送进度
- 通知步骤完成、错误、最终结果

</details>

<details>
<summary>🔀 步骤类型和执行</summary>

**Agent 调用步骤**
- 调用指定 Agent 执行推理
- 输入：Agent ID、提示词或用户消息
- 输出：Agent 返回结果

**工具调用步骤**
- 直接调用 MCP 工具
- 输入：工具名、参数
- 输出：工具执行结果

**条件分支**
- 基于条件表达式选择路径
- 支持 if-then-else 逻辑
- 访问步骤输出变量

**循环处理**
- For 循环：遍历集合
- While 循环：重复直到条件满足
- 循环计数器和数据访问

**数据转换**
- 数据映射和格式转换
- 变量赋值和表达式计算
- 使用模板引擎处理

**延迟等待**
- 等待指定时间后继续

</details>

```csharp
    /// <summary>执行状态：running, completed, failed, canceled</summary>
    public string Status { get; set; }

    /// <summary>错误信息</summary>
    public string? ErrorMessage { get; set; }

    /// <summary>执行耗时（毫秒）</summary>
    public long DurationMs { get; set; }

    /// <summary>已执行的步骤数</summary>
    public int ExecutedStepCount { get; set; }

    /// <summary>创建时间</summary>
    public DateTime CreatedAt { get; set; }

    /// <summary>完成时间</summary>
    public DateTime? CompletedAt { get; set; }
}

// 工作流定义 DTO
public class WorkflowDefinitionDto
{
    public Guid Id { get; set; }
    public string Name { get; set; }
    public string Description { get; set; }
    public object Definition { get; set; }
    public string[] Tags { get; set; }
    public string Status { get; set; }
}

// 工作流步骤定义
public class WorkflowStepDefinition
{
    public string Id { get; set; }
    public string Name { get; set; }
    public string Type { get; set; } // agent_call, tool_call, condition, loop, data_transform, delay
    public object Config { get; set; }
    public string[] NextStepIds { get; set; }
}
```

### 关键实现点

- **步骤编排**：支持顺序、并行、条件分支执行
- **上下文传递**：步骤间通过变量传递数据
- **错误处理**：支持重试、降级、中止策略
- **进度跟踪**：完整的执行步骤记录
- **异步处理**：长时间工作流使用异步执行
- **状态持久化**：工作流执行状态完整保存便于恢复

## 开放平台 API

### API 设计原则

- **RESTful 风格**：使用 HTTP 动词（GET、POST、PATCH、DELETE）表达操作
- **资源导向**：端点以资源名词命名
- **版本控制**：使用 URL 路径表达版本（如 `/api/v1/`）
- **WebSocket 支持**：实时功能使用 WebSocket 连接
- **OpenAPI 文档**：遵循 OpenAPI 3.1 规范

### 主要资源

| 资源 | 功能 | 端点 |
|------|------|------|
| App | 应用的 CRUD 与配额 | `/api/v1/apps` |
| Agent | Agent 的 CRUD 和调用 | `/api/v1/agents` |
| Workflow | 工作流的 CRUD 和执行 | `/api/v1/workflows` |
| KnowledgeBase | 文档上传和知识库查询 | `/api/v1/rag/documents`, `/api/v1/rag/search` |
| MCP Tools | 工具注册和查询 | `/api/v1/tools` |
| Model | 模型信息查询 | `/api/v1/models` |
| SystemConfig | 系统配置与提示词 | `/api/v1/system-configs` |

### 实现框架

**基于 Perigon 模板**：
- 所有 API 遵循 Perigon 约定
- 使用 Manager 模式处理业务逻辑
- DTO 用于数据转换
- 自动生成错误响应
- 支持国际化和本地化

### API 文档

- 所有端点的请求/响应格式在 Swagger UI 中自动生成
- 使用 XML 注释提供接口说明
- 提供 OpenAPI 3.1 规范文件供客户端生成

```
src/

├── Modules/
│   ├── AIAgentMod/                # AI Agent 模块
│   │   ├── Managers/              # Agent 业务逻辑
│   │   ├── Models/                # DTO 定义
│   │   └── ModuleExtensions.cs    # 模块注入
│   ├── CommonMod/                 # 通用模块（模型调用封装）
│   │   ├── Managers/
│   │   └── Models/
│   ├── ModelMod/                  # 模型与应用管理模块
│   ├── KnowledgeBaseMod/          # 知识库与 RAG 模块
│   ├── McpMod/                    # MCP 工具模块
│   ├── WorkflowMod/               # 工作流模块
│   └── SystemMod/                 # 系统配置模块
└── Services/
    ├── ApiService/                # 公开 API 服务
    └── AdminService/              # 管理后台服务
```

### 开发规范

1. **实体定义**：在 `Definition/Entity` 按模块组织
2. **业务逻辑**：在 `Modules/XXXMod/Managers` 中实现
3. **DTO 模型**：在 `Modules/XXXMod/Models` 中定义
4. **API 端点**：在 `Services/ApiService` 中声明
5. **依赖注入**：在 `ModuleExtensions.cs` 中配置

### Manager 模式

每个核心功能都有对应的 Manager 类：
- `ApplicationManager`：应用管理
- `ModelManager`：模型管理
- `ModelProviderManager`：模型提供商配置
- `RagDocumentManager`：文档管理
- `RagSearchManager`：知识库查询
- `AgentManager`：Agent 管理
- `AgentExecutionManager`：Agent 执行
- `WorkflowManager`：工作流管理
- `ToolManager`：工具管理
- `SystemConfigManager`：系统配置与提示词

Manager 职责：
- 业务逻辑实现
- 数据验证和处理
- 调用数据访问层
- 事件发送
